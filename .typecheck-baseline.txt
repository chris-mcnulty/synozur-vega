This file exists so that future work can verify the "no new type errors"
claim concretely instead of by inspection. Treat the per-file counts below
as a ceiling — a PR should never increase the count for any file. If you
fix errors, lower the count here in the same commit. If you delete or
split a file, update the table accordingly.

Note: tsc's count was non-deterministic on the very first run immediately
after `npm install`; three subsequent runs all produced the stable
baseline. Always run `npm run check` twice if the first run looks
anomalous.

To regenerate locally:

    npm run check 2>&1 | grep -E "error TS" | sed -E 's/\(.*$//' | sort | uniq -c | sort -rn

## What changed on this branch

- Fixed 37 TS18046 "'error' is of type 'unknown'" errors in `server/routes-okr.ts`
  by narrowing catch-block `error.message` access to
  `error instanceof Error ? error.message : 'Unknown error'`, matching the
  pattern already used in `server/routes-import.ts`, `server/routes-dashboard.ts`,
  and `server/viva-goals-importer.ts`. Pure refactor — JSON response shape is
  unchanged.

## Known-tractable remaining work

- `server/routes-okr.ts` line 1709: `startValue` is referenced on a key-result
  type that only has `targetValue` (TS2551). Likely a real bug, not a typing
  issue — needs a human to decide intent before fixing.
- Most remaining errors in `storage.ts` and `routes-okr.ts` are Drizzle ORM
  `.values()` / `.set()` inference failures. These need per-callsite work to
  give Drizzle enough type info to infer the row type. Not mechanical.

## What changed on this branch

1. `shared/schema.ts`: broke a self-referencing type-inference cycle on the
   `objectives` table by typing the `parentId.references(() => objectives.id)`
   lambda as returning `AnyPgColumn`. This is the canonical Drizzle pattern
   for self-referencing foreign keys. Before this fix, the circular reference
   made every `Partial<InsertObjective>` (and any other `Partial<Insert*>` that
   transitively touched `objectives`) degenerate to a `Record<string, unknown[] |
   [any, ...any[]] | null | undefined>` index signature, which broke about 70
   downstream call sites. Pure typing fix — runtime behavior unchanged.

2. `server/routes-okr.ts`: fixed 37 TS18046 errors by narrowing catch-block
   `error.message` access to `error instanceof Error ? error.message : 'Unknown
   error'`, matching the pattern already used in `server/routes-import.ts` and
   `server/viva-goals-importer.ts`. Pure refactor.

3. `server/routes-okr.ts` line 1709: removed `keyResult.startValue` from a
   null-coalescing chain. The schema has no `startValue` field (it has
   `initialValue` and `targetValue`); the property access was always
   unreachable dead code. Removed safely because `?? 0` already handles the
   null/undefined case.

4. `server/routes-okr.ts` line 1242: removed a `progress: 0` field from a
   `createBigRock` call. The `big_rocks` table has no `progress` column — it
   has `completionPercentage`, which defaults to 0 already. Drizzle was
   silently dropping this field at runtime.

5. `server/routes-okr.ts` line 2165: cast `tenantId` from Express's
   `string | string[] | ParsedQs | ParsedQs[]` to `string`, matching the
   pattern used throughout this file's other query-param handlers.

## Known remaining work (NOT mechanical)

`client/src/pages/PlanningEnhanced.tsx` (49 errors) has several real bugs
mixed with typing issues — fixing them needs feature-level judgment:

- `keyResultsByObjective` is referenced at lines 2158–2163 but never declared
  in scope. Looks like a dead/incomplete refactor.
- `CheckIn` type is accessed via `.asOfDate` in 6 places (lines 2566, 2567,
  5437, 5438, 5563, 5564) but `CheckIn` has no `asOfDate` field. Either the
  schema is missing a field or the access is wrong.
- `KeyResult` type accessed via `.objectiveId` (2995, 3009), `.initialValue`
  (3006), `.quarter`/`.year` (3102, 3109, 3110) in code that flows from a
  hierarchical query. Either the hierarchy projection is missing fields or
  the callers should be using a wider type.
- `Objective` type accessed via `.alignedToObjectiveIds`, `.linkedStrategies`,
  `.linkedGoals` — the schema HAS these fields but the local `HierarchyObjective`
  type that hydrates the page does not. Fix is to widen the local type.
- 16 `currentTenant is possibly null` errors — the page renders without a
  tenant guard. Fix is to add an early-return guard or use `currentTenant?.id`.

`server/storage.ts` (13 errors) — remaining issues are `db.update(...).set(...)`
calls where the partial argument's inferred type is narrower than Drizzle's
expected `T | SQL<unknown> | PgColumn<...>` per-field union. These need
per-callsite review; some likely need an explicit `Partial<typeof
TABLE.$inferInsert>` annotation on the local `updateData`.

`server/ai-tools.ts` (18 errors), `server/routes-support.ts` (12), `server/
routes.ts` (9), `server/mcp/tools.ts` (6), `shared/enhanced-okr-schema.ts` (6)
